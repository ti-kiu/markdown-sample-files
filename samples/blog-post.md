# Why I Read Markdown Files in the Browser Instead of an App

*Published 2026-03-02 · 4 min read*

Every developer I know has a "markdown app" they stopped using within a
month. The files were fine — the friction was everything around them:
installers, accounts, sync, updates.

> Markdown is meant to be readable as-is, without looking like it's been
> marked up with tags or formatting instructions.
> — John Gruber, 2004

That line is the whole argument. If a `.md` file needs an app to be read,
we've drifted from the idea.

![Browser window with a rendered markdown doc](https://picsum.photos/seed/mdblog/640/320)

*Reading a release notes file in the browser — nothing uploaded, nothing installed.*

## What I actually do

1. A link to someone's `README.md`? Open it in a viewer tab.
2. Downloaded docs? Drag the file into [Markdown File Viewer](https://markdownfileviewer.com)
   and read it rendered, locally.
3. Writing my own? Any text editor works — that's the point of the format.

## The counter-argument

Apps give you sync, search across thousands of notes, and mobile capture.
True! For a personal *library*, use an app. For just *reading the file
in front of you*, nothing beats a zero-friction page that renders it and
gets out of the way.
